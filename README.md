# Richard Trip

QA analyst. I have spent the last ten years inside the systems of a bank six years running the night batch processes that had to finish before the branches opened, and the last four testing changes before they reached production.

That is where I learned what matters most to me in testing a defect is not just a line in a report. It can be a wrong balance, a blocked transfer or a customer who cannot pay. So I start with the risk, and then I decide what to test, giving priority to the interests of the business.

## What I do

- Functional and end-to-end testing of core banking systems and third-party integrations
- Certification tests with clearing houses, payment networks and ATM networks
- Controlled tests in production, when a scenario cannot be reproduced in QA
- Test data preparation with SQL and defect tracking in Jira

## Projects

These three repositories use public demo applications. Each one has a test plan, the results of a real execution and the defects I found.

- [manual_test_case](https://github.com/trip-rich-15/manual_test_case) - Manual testing of fund transfers in a demo bank. Risk-based plan, 5 test cases and 4 defects with evidence. One of them allows a transfer without enough balance.
- [booker-api-testing](https://github.com/trip-rich-15/booker-api-testing) - API tests for a hotel booking service with Postman. An end-to-end flow that passes the token and the booking ID between requests, negative tests, and Newman running in GitHub Actions on every push.
- [automation_suite](https://github.com/trip-rich-15/automation_suite) - E2E automation for an online store with Playwright, Python and Gherkin (pytest-bdd). Page Object Model, Chromium and Firefox in CI, and known defects kept visible as strict expected failures.
